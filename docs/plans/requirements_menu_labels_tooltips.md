# Requirements Document: Menu Labels Sanitization & Universal Tooltip Coverage

## Introduction

`revamped-newbspguy` is a GoldSrc/Quake engine BSP map editor and manipulator. Following recent modularization and theme improvements, several menu strings contain formatting anomalies (e.g., embedded tab and shortcut strings inside localization keys such as `"Go to...\tCtrl+G"`), spelling typos (`"intenal"` instead of `"internal"`), raw shortcut labels in context menus (`"ALT+G"`, `"Ctrl+V"`), and over 84% of interactive menu options lack hover tooltips or have informal/incomplete descriptions. Furthermore, legacy menu planning documents remain in the repository root.

This document establishes the functional and non-functional requirements for:
1. Deleting obsolete menu planning documents from the repository root.
2. Sanitizing all localization keys and menu labels across English, Russian, and Chinese catalogs.
3. Establishing 100% hover tooltip coverage across the Main Menu Bar (241 items) and Viewport Context Menus (84 items) with technically accurate, detailed explanations.
4. Aligning menu shortcut arguments with the centralized `ActionRegistry`.

---

## Glossary

- **BSP (Binary Space Partitioning)**: The compiled geometry and spatial indexing map format utilized by GoldSrc and Quake engines.
- **Clipnode**: Spatial collision binary tree nodes used by the engine for player, monster, and vehicle collision hulls.
- **Hull**: Specific collision hull index (Hull 0: Point/Raycast/Visual, Hull 1: Humanoid, Hull 2: Large Vehicle/Monster, Hull 3: Ducking/Head).
- **Lump**: An indexed data section in the BSP file (e.g., vertices, planes, faces, textures, lighting, entities, clipnodes).
- **Lightmap**: Precomputed surface luminance/color sample data generated by radiosity (RAD) compilers.
- **ImGui Tooltip**: Hover popup rendered when `ImGui::IsItemHovered()` and the cursor dwell duration exceeds `g_tooltip_delay`.
- **ActionRegistry**: Centralized engine command and shortcut dispatcher providing consistent action names, categories, shortcuts, and descriptions.
- **`LANG_` Catalog**: Localization keys mapped in `resources/languages/language*.ini` files for runtime internationalization.

## Requirements

### Requirement 1: Repository Root Markdown Cleanup
**User Story:** As a developer/maintainer, I want obsolete planning files removed from the repository root so that the root directory remains clean and uncluttered.

#### Acceptance Criteria
1. THE system SHALL delete `menu_original.md` from the repository root.
2. THE system SHALL delete `menu_reordered.md` from the repository root.
3. THE system SHALL preserve `README.md` and all other documentation in `docs/`.

---

### Requirement 2: Localization Catalog & Label Sanitization
**User Story:** As a user of any supported language, I want menu item labels to display clean, properly formatted titles without embedded tab characters or shortcut codes.

#### Acceptance Criteria
1. THE system SHALL update `LANG_1095` in `resources/languages/language.ini`, `language_ru.ini`, and `language_zh.ini` to contain only the label string (`"Go to..."`, `"Перейти к..."`, `"转到..."`) without any trailing `\t` or shortcut strings.
2. THE system SHALL pass the shortcut `"Ctrl+G"` explicitly as the second parameter in `ImGui::MenuItem` in `src/editor/gui/GuiMenuBar.cpp`.
3. THE system SHALL fix the typo `"intenal"` to `"internal"` across all affected localization keys (`LANG_0469`, `LANG_0470`, `LANG_1071`, `LANG_1072`, `LANG_1155`, `LANG_1156`, `LANG_1174`, `LANG_1175`).
4. THE system SHALL replace raw shortcut strings used as menu titles in `src/editor/gui/GuiContextMenu.cpp` (such as `LANG_0441` `"Ctrl+V"` and `LANG_0473` `"ALT+G"`) with meaningful action titles (`"Paste with BSP Model"`, `"Grab / Move"`).

---

### Requirement 3: Main Menu Bar Hover Tooltip Coverage (100%)
**User Story:** As a mapper, I want clear, informative hover tooltips on every single menu option and submenu in the top menu bar so that I understand what each tool and format preset does.

#### Acceptance Criteria
1. THE system SHALL provide an `IMGUI_TOOLTIP` or tooltip popup on every interactive `ImGui::MenuItem` across all 8 menu categories in `GuiMenuBar.cpp`:
   - **File Menu**: All Save, Save As presets, Open, Close, Export, Import, Sven Test, Merge, Recent Files, Reload, Validate, Settings, and Exit options.
   - **Edit Menu**: Undo, Redo, Cut, Copy, Paste variants, Delete, Selection tools, BSP duplication, Face splitting, Transform, and Keyvalues.
   - **View Menu**: Command Palette, Clipnode hulls, Unhide, Panel toggles, GOTO teleport, Show Limits, and Skybox rendering.
   - **Map Menu**: Entity Report, Show Limits, Clean, Optimize, Map Transformations (Mirror, Rotate, Scale), Recompile Lighting, and Generate Nav Mesh.
   - **Tools Menu**: Hull Deletion, Hull Redirection, Cull actions, Geometry Fixes, Additional Tools (OOB data, Model deduplication, Surface extents), and Experimental tools.
   - **Create Menu**: Point entities, Passable models, Solid models, Trigger volumes, Clip brushes, and Random DM spawn points.
   - **Windows Menu**: Developer Console and Map Tab switcher entries.
   - **Help & Debug Menus**: Help dialogs, About, Texture dumps, and Perimetric Skybox creation.
2. WHEN the user hovers over any menu item for longer than `g_tooltip_delay`, THE system SHALL render the tooltip explaining the tool's function, preconditions, and potential caveats.
3. THE system SHALL replace all informal debug strings (e.g., *"I don't know for what it needs :)"*) with technically accurate documentation.

---

### Requirement 4: Viewport Context Menu Tooltip Coverage (100%)
**User Story:** As a 3D level editor, I want comprehensive tooltips on all viewport context menu options (Face, Object, and Selection context menus) so that quick right-click actions are clearly understood.

#### Acceptance Criteria
1. THE system SHALL add `IMGUI_TOOLTIP` calls to all 84 interactive items and submenus in `src/editor/gui/GuiContextMenu.cpp`.
2. THE tooltips SHALL detail face texture alignment, lightmap copying, face style cloning, selection expansion, model origin alignment, collision hull generation, and BSP duplication.

---

### Requirement 5: Shortcut & ActionRegistry Consistency
**User Story:** As an advanced user, I want keyboard shortcuts displayed on menu items to strictly match the global keybindings and ActionRegistry.

#### Acceptance Criteria
1. THE system SHALL ensure all shortcuts displayed in `GuiMenuBar.cpp` and `GuiContextMenu.cpp` match the registered shortcuts in `ActionRegistryInit.cpp` and `Renderer.cpp`.
2. WHERE a shortcut is available, THE system SHALL pass it via the standard `const char* shortcut` parameter of `ImGui::MenuItem`.

---

### Requirement 6: Build Verification & Zero Regressions
**User Story:** As a project contributor, I want the codebase to compile cleanly across MSVC and GCC/Clang with zero warnings or broken layouts.

#### Acceptance Criteria
1. THE codebase SHALL build successfully with CMake and MSVC in Release mode.
2. THE application SHALL launch and render all menus cleanly without text overflow, misaligned shortcut columns, or visual clipping.
